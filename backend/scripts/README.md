# إصلاح صور العقارات (Fix Property Images)

سكريبت صيانة **معزول** (standalone) لأنظمة لينكس مثل Railway، مهمته ضمان أن كل
عقار في التطبيق تُعرض صوره:

1. يتحقق لكل سجل في `property_images` أن الملف المطابق موجود فعليًا على الخادم
   في المسار النسبي المتوقع (تحت `storage/app/public`).
2. كل ملف مفقود: يحمّله من مصدر ويخزّنه بالاسم الصحيح `0.jpg` / `1.jpg` /
   `2.jpg` في مجلد العقار.
3. كل سجل كان مساره رابطًا خارجيًا مطلقًا (`https://...`): يُعاد ربطه بملف
   محلي إما بالتحميل أو بالبديل دون إنترنت.
4. العقار بلا صور: تُنشأ له ثلاثة سجلات صور مرتبطة بالملفات.
5. عقار بلا صورة غلاف: تُجعل الصورة الأولى (الترتيب 0) غلافًا.

## لماذا؟

- **القرص المؤقت في Railway**: ملفات الصور التي تُنشئها البذور تُمسح عند كل
  إعادة نشر بينما تبقى سجلات قاعدة البيانات، فيعرض التطبيق صورًا مكسورة (404).
- **قيود جغرافية / حجب CDN**: بعض الشبكات في اليمن لا تصل إلى خدمات أمثال
  Unsplash. لذا يحاول السكريبت عدة مصادر بالترتيب وينتهي دائمًا ببديل محلي
  يُولَّد بـ GD — لا يعتمد أبدًا على نجاح الشبكة.

## التشغيل

من مجلد `backend/` (يتطلب PHP 8.2+ مع ext: `curl`، `gd`، `pdo_mysql`):

```bash
# فحص فقط دون أي تغيير
php scripts/fix_property_images.php --dry-run

# تعبئة الفراغات فقط (الوضع الافتراضي — آمِن للتشغيل المتكرر)
php scripts/fix_property_images.php

# إعادة توليد كل الصور من المصادر (لا يمسح، يستبدل الملفات فقط)
php scripts/fix_property_images.php --regen

# عقار واحد بالكود أو المعرّف
php scripts/fix_property_images.php --property=SN-2026-001
php scripts/fix_property_images.php --property=12 --regen

# عدد محدود
php scripts/fix_property_images.php --limit=5
```

## على Railway

```bash
railway run php scripts/fix_property_images.php
```

أو فعّل **الشفاء الذاتي** الذي يتشغّل تلقائيًا بعد كل إعادة نشر: أضف متغير
البيئة في خيارات الخدمة:

```
WJ_RUN_IMAGE_FIX = 1
```

(الإدخال `backend/entrypoint.sh` يشغّل السكريبت عند كل إقلاع، وهو آمن لعمليات
التكرار، وعدم نجاحه لا يُسقط الخدمة).

> متغيرات الاتصال تأتي من بيئة Trekway/الخادم نفسها (نفس `.env` التي يعمل
> عليها `php artisan`)، فالسكريبت لا يحتاج أي إعداد إضافي.

## التخفيف الدائم (اختياري)

حتى لا تتكرر المشكلة أصلًا، فعّل **Volume** في Railway على المسار:

```
storage/app/public
```

بهذا تبقى الصور على قرص دائم ولا تُمسح مع كل إعادة نشر، ويبقى السكريبت في
الخلفية كشبكة أمان لأي سجل جديد.

## ما لا يفعله السكريبت

- لا يلمس بيانات العقارات (عنوان/سعر/حالة) إلا حقل `path` في `property_images`
  وسجل الغلاف عند غيابه.
- لا يحذف صورًا ولا يعيد ترقيم الملفات الموجودة الصحيحة.
- لا يلزم وجود ترخيص خارجي؛ البديل المحلي يولّد صورة JPEG صالحة دائمًا.
